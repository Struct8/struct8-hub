# Architecture

Four ports, one rule, and a handful of seams deliberately left open.

**The rule: the core imports no cloud SDK.** Not `@aws-sdk/*`, not `boto3`'s equivalent, nothing.
Everything that talks to a cloud registers itself from the outside. This is what makes the core
testable offline in milliseconds, and it is what makes a second cloud additive instead of
invasive.

---

## The ports

```ts
type Discovery = (source: unknown) => Neighbor[];
type Ingress   = (raw: unknown) => Arrival | Promise<Arrival>;
type Sender    = (n: Neighbor, e: Envelope, ctx: Ctx) => Promise<void>;
type Report    = { trace: string; origin: string; hops: Hop[] };
```

The core is one function over them:

```ts
hub.handle(arrival: Arrival, neighbors: Neighbor[], ctx: Ctx): Promise<Report>
```

It performs no I/O of its own. Everything it does, it does through a port.

## What actually varies between runtimes

Less than it looks. Discovery, normalization, fan-out and reporting are identical everywhere. Two
things change:

| | how the message arrives | how the process lives |
|---|---|---|
| AWS Lambda | the platform calls the handler | one shot |
| Azure / GCP Functions | the platform calls the handler | one shot |
| Cloudflare Workers | the platform calls `fetch` / `queue` / `scheduled` | one shot |
| Container / VM | **nothing calls anything** — it must poll | long-running |

The first three are a shim of ten to twenty lines. The last one is not, and it is honest to say
so: a container has to do for itself what the platform does for free elsewhere. It needs a poller
per source type, and it needs the incoming side of the contract, which
[does not exist yet](../CONTRACT.md#known-gaps).

## Growth: one folder per resource

```
src/
  core/          ← never changes when a resource is added
    discovery.ts
    envelope.ts
    registry.ts
    report.ts
    hub.ts
  resources/
    aws_sqs_queue/index.ts
    aws_s3_bucket/index.ts
  runtimes/
    lambda.ts
```

```ts
export interface ResourceModule {
  type: string;                  // 'aws_sqs_queue'
  keys?: string[];               // extra grammar keys it uses: ['QUEUE_URL']
  capabilities?: Capability[];   // ['queue']
  send?: Sender;                 // how to reach it
  receive?: Ingress;             // how to read an event coming from it
}
```

**The parser's vocabulary is derived from the registry.** `type` feeds the type list, `keys` feeds
the key list. Registering a resource makes it discoverable and reachable in the same act.

This closes a failure mode that the predecessor of this package documented in its own header: a
type listed in the parser's vocabulary but missing a way to be reached is recognized, produces a
neighbor, and then silently does nothing. Deriving one list from the other removes the possibility
rather than warning about it.

The barrel that imports every resource is **generated by a script**, not discovered at runtime.
Runtime discovery needs a filesystem or a bundler plugin; Cloudflare Workers has neither, and
static imports are what lets unused resources be tree-shaken away.

### Why the generated shim names its resources

```js
import { hub } from '@struct8/hub';
import '@struct8/hub/r/aws_sqs_queue';
import '@struct8/hub/r/aws_s3_bucket';
export const handler = hub.lambda();
```

The generator knows what is in the diagram, so it imports only that. The catalog can grow without
bound and **no deployment gets heavier**. On Workers, where bundle size is capped, this stops
being tidiness and becomes a requirement.

## The envelope

```ts
type Envelope = { trace: string; hops: number; path: string[]; at: string; body: string };
```

`hops` decrements at every forward and stops at zero. `path` accumulates the chain.

This replaces loop control by substring search — checking whether the workload's own name appears
somewhere in the message text. That check fails in both directions: a legitimate message that
happens to mention the resource suppresses itself, and a suppressed item is not reported as
failed, so on a batched source the checkpoint advances and the record is gone. A counter cannot
be fooled by content.

`trace` is what makes a four-hop chain one story instead of four unrelated logs, and it is what a
diagram needs to color a wire green.

## Seams left open

Cross-provider wiring is out of scope for now. These are the places where it will attach, listed
so that nothing gets built across them by accident.

**Identity is a port, not a parameter.** The sender for a queue is the same code in a Lambda, a
container and a VM; what differs is where the credential comes from. Keeping identity separate is
what keeps the work at *(resources + runtimes)* instead of *(resources × runtimes)*.

**`Neighbor.handle` is reserved.** Where a platform delivers a live object instead of an
identifier, it lands here. The sender's shape becomes `if (n.handle) …native… else …HTTP…` — one
branch inside one sender, never a parallel implementation.

**Capability is not permission.** `capabilities` answers *may this wire be drawn?*. What the wire
is allowed to do is a separate output, and the day they merge, the ability to refuse a wire at
drawing time is lost — which is the cheapest place to refuse one.

**Transport is `fetch`.** Every target runtime has it natively. A sender that reaches for a
platform-specific HTTP client closes a door for no gain.

## Testing

Two suites, and the split matters.

**Conformance** iterates the registry and asserts the invariants on every registered resource:
that its capability exists, that its sender survives a neighbor missing a value, that it records a
hop, that it does not throw on an empty message. Adding a resource gets it tested without anyone
writing a test — which is what keeps the fortieth resource as good as the first.

**Contract** runs against real generator output, for the reason given in
[CONTRACT.md §9](../CONTRACT.md#9-conformance).
